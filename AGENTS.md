# Agent rules
- The maintenance handoff is content-addressed: generate its allowlisted manifest and deterministic archive with tools/export-package.py; receipt/checksums form an external envelope, avoiding self-referential hashes and excluding standalone/demo data.
- Corrective descriptive edits use a tenant-scoped locked RPC with expected updated_at; only existing descriptive fields are writable, preserving entries, detection/completion dates, incidents and preventive schedules. Reactivation is an explicit independent authorized choice.
- Suggested maintenance is a shared versioned declarative catalog; applying only fills the existing plan form with editable values and requires asset selection and frequency review, preserving stable plan codes across revisions for duplicate checks — avoids automatic scheduling and parallel plan engines. No SQL seed of suggestions: the portable domain catalog is the single source for both hosts.
- Maintenance screens live in `src/modules/maintenance/ui/pages`; route files are thin wrappers (path/head/component) — keeps the module portable to ICORE.
- Maintenance services get data only via `getRepositories()` (contracts/registry); the host registers one adapter at startup (`src/router.tsx`) — lets ICORE plug its adapter without touching services/UI.
- Module UI reads org/user/role and the attachments slot from `ui/host.tsx` (`MaintenanceUiProvider`), never from app contexts — keeps request context explicit per tree (SSR-safe).
- `adapters/standalone/` is this app's host and is excluded from the ICORE export; enforced by `ui/__tests__/module-boundary.test.ts`.
- Physical deletes of maintenance assets/plans/links/sessions/items go only through `mnt_sa_delete_*` / `mnt_sa_unlink_plan_asset` RPCs (standalone) and `mnt_delete_*` / `mnt_unlink_plan_asset` (ICORE installer); BEFORE DELETE guards block direct deletes — keeps evidence and the due-date log intact.
- Safe-delete trigger authority must include the effective database role, never a client-set custom GUC alone — prevents bypassing the approved RPC checks.
- Technical sheets: profiles are declared in `src/modules/maintenance/domain/technical-profiles.ts` (system catalog), enabled per org type via `asset_types.metadata.technical_profile`, values stored typed in `assets.metadata.technical` and shape-checked by trigger `mnt_tg_technical_sheet_guard` — no per-device columns, reusable by other ICORE modules.
- Plan classification uses stable codes `maintenance_plans.plan_nature` / `requirement_origin` (domain/plan-classification.ts); origin is never inferred and defaults to `unspecified` — keeps regulatory filters trustworthy and ICORE-portable.
- AssetPicker is a controlled presentation-only multi-selector over existing org-scoped ScopeAsset candidates; shared pure search uses host-provided location ancestors and retains off-search selection, with paged rendering — avoids a parallel data layer and keeps eligibility/permissions in existing services/RLS. Remount plan forms on org changes to isolate transient selections.
- Metrology equipment optionally references one inventory asset (`asset_id`, same org, set-once, unique, ON DELETE RESTRICT); when linked, displayed code/name/location come from the asset — keeps one physical identity without rewriting metrology history.
- Metrology operational association uses separate `parent_asset_id` (same org, N:1, no reassignment, ON DELETE RESTRICT) and an invoker-rights locked batch RPC; identity-linked redundant names are excluded from updates and guarded in SQL — prevents confusing installations with physical identity while keeping RLS authoritative.
- Metrology creation from an asset navigates to the existing list form using validated search parameters; successful creation replaces the origin URL — reuses one form and prevents navigation from replaying an already completed creation.
- QR execution is authenticated-only: tokens resolve through the `mnt_resolve_scan`/`mnt_sa_resolve_scan` RPCs as the caller (membership + run + session assignment, generic `not_available`), never via public routes or admin clients; mobile UI stays router-free and hosts supply wrappers.
